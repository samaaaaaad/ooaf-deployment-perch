# Architecture Decision Records

Architecture Decision Records (ADRs) preserve the reason behind significant technical choices so the team can review or supersede them deliberately.

| ADR | Decision | Status |
|---|---|---|
| [0001](0001-use-h2-for-mvp-development.md) | Use H2 for MVP development and testing | Accepted |
| [0002](0002-separate-events-venues-and-sessions.md) | Separate productions, physical venues and dated sessions | Accepted |
| [0003](0003-use-local-credential-authentication-for-mvp.md) | Use local credentials and server-side sessions for the MVP | Accepted |
| [0004](0004-issue-tickets-with-booking-confirmation.md) | Issue tickets atomically with booking confirmation | Accepted |
| [0005](0005-store-display-location-and-category-on-events.md) | Store display location and category on events | Accepted |

Accepted ADRs describe the current direction. If the direction changes, add a new ADR and identify which earlier decision it supersedes.
